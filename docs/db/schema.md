# Схема базы данных для RAG-системы BusiVerse

## Обзор

База данных спроектирована для хранения документации BusiVerse в виде чанков с векторными эмбеддингами для семантического поиска и полнотекстового поиска по русскому языку.

## Таблицы

### `sources`
Исходные документы, которые были разбиты на чанки.

| Поле | Тип | Описание |
|------|-----|----------|
| `source_id` | TEXT (PK) | Уникальный идентификатор документа |
| `title` | TEXT | Название документа |
| `doc_version` | TEXT | Версия документа |
| `valid_from` | DATE | Дата актуальности документа |
| `content_hash` | TEXT | SHA-256 хэш содержимого для идемпотентного ре-ингеста |

### `chunks`
Отдельные фрагменты контента с эмбеддингами для векторного поиска.

| Поле | Тип | Описание |
|------|-----|----------|
| `chunk_id` | TEXT (PK) | Уникальный идентификатор чанка |
| `source_id` | TEXT (FK) | Ссылка на источник |
| `business_type` | TEXT | Ниша бизнеса: `coffee_shop`, `pickup_point`, `mini_bakery`, etc. |
| `block` | TEXT | `offline`, `online` или `global` |
| `section_code` | TEXT | Код секции: `1.3`, `B0.2`, `0`, `11` |
| `section_title` | TEXT | Заголовок секции |
| `block_title` | TEXT | Заголовок блока внутри секции |
| `heading_path` | TEXT[] | Иерархический путь: `["1. ОФЛАЙН — КОФЕЙНЯ", "1.3. Финансовая модель", ...]` |
| `chunk_type` | TEXT | Тип контента: `case`, `sop`, `table`, `checklist`, `prose` |
| `topics` | TEXT[] | Извлеченные темы/термины |
| `scope` | TEXT | `global` (для всех ниш) или `business` (специфично для ниши) |
| `parent_id` | TEXT | ID родительского чанка (для small-to-big retrieval) |
| `chunk_index` | INTEGER | Порядковый номер внутри секции |
| `line_start` | INTEGER | Начальная строка в исходном файле |
| `line_end` | INTEGER | Конечная строка в исходном файле |
| `token_count` | INTEGER | Количество токенов в чанке |
| `text` | TEXT | Текст чанка |
| `content_hash` | TEXT | SHA-256 хэш текста |
| `tsv` | TSVECTOR | Generated column для полнотекстового поиска (russian) |
| `embedding` | VECTOR(1024) | Векторное представление для семантического поиска |

#### Индексы для `chunks`

| Индекс | Тип | Описание |
|--------|-----|----------|
| `chunks_embedding_idx` | HNSW | Векторный поиск с косинусным расстоянием |
| `chunks_tsv_idx` | GIN | Полнотекстовый поиск по русскому языку |
| `chunks_filter_idx` | B-tree | Фильтрация по `business_type` и `section_code` |
| `chunks_scope_idx` | B-tree | Фильтрация по `scope` (global/business) |
| `chunks_parent_idx` | B-tree | Поиск дочерних чанков по `parent_id` |

### `chunk_links`
Внутренние ссылки между чанками (например, "см. раздел B0").

| Поле | Тип | Описание |
|------|-----|----------|
| `from_chunk_id` | TEXT (FK) | Чанк, содержащий ссылку |
| `to_section` | TEXT | Код секции, на которую ссылаются |

PK: `(from_chunk_id, to_section)`

## Выбор размерности вектора

Зафиксирована размерность **1024** как самая универсальная:
- Поддерживается большинством современных моделей эмбеддингов
- Matryoshka-модели позволяют усечение без изменения схемы
- На корпусе ~600 чанков смена размерности занимает минуты

## Полнотекстовый поиск

Используется встроенная конфигурация PostgreSQL `russian`:
- Автоматическая стемматизация русских слов
- Поддержка стоп-слов
- Оптимизация для юридической и налоговой лексики
- Не требует внешних сервисов

## Retrieval Pipeline

```
Запрос пользователя
  │
  ├─ 1. Определить business_type (селектор UI + классификатор fallback)
  │
  ├─ 2. Фильтр: WHERE business_type = $1 OR scope = 'global'
  │
  ├─ 3. Параллельные поиски:
  │     - Vector: top-50 по cosine distance
  │     - Fulltext: top-50 по to_tsquery('russian', ...)
  │
  ├─ 4. RRF (Reciprocal Rank Fusion) → top-20
  │
  ├─ 5. Rerank → top-5..8
  │
  ├─ 6. Small-to-big: подтянуть parent-чанк если нужен контекст
  │
  └─ 7. Разрешить ссылки через chunk_links
```

## Контракт с проектом ассистента

Ассистент (отдельный проект) читает ту же Neon-базу. Схема БД — это контракт между репозиториями.

**Что должен знать проект ассистента:**
- Таблицы для чтения: `chunks`, `sources`, `chunk_links`
- Поля для фильтра: `business_type`, `scope`, `section_code`
- Поле для векторного поиска: `embedding`
- Поле для полнотекстового поиска: `tsv`
- Поля для цитат: `heading_path`, `section_title`, `block_title`, `line_start`, `line_end`

**⚠️ ВАЖНО:** Модель эмбеддингов для запроса и для чанков должна быть одинаковой. Если разойдутся — векторный поиск вернёт мусор без ошибок в логах.
