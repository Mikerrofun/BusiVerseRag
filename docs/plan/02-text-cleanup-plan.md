**Это не дубликаты. Это структура.** У каждой ниши свой «Рыночный фон» с своими цифрами. Если их дедуплицировать, документ потеряет 90% содержания.

Проверка на настоящие дубликаты: длинных строк (>120 символов), встречающихся больше одного раза, в документе **ровно одна** — это дисклеймер про файл финмоделей, который честно повторяется в каждой нише.

**Вывод: план очистки — это не про дедупликацию. Это про ремонт повреждённых таблиц и снятие мусорной разметки.**

## 2. Что чистим механически

Это безопасные правки: скрипт, детерминированный результат, ничего не выдумывается.

### 2.1 Снять HTML-разметку

**`<br>` — 11 263 штуки.** Внутри ячеек таблиц `<br>` означает перенос строки внутри ячейки. Просто удалить нельзя — склеятся слова. Правильно: заменить на пробел, затем схлопнуть повторные пробелы.

```
Было:  |Переменная<br>часть (% или KPI)|
Стало: |Переменная часть (% или KPI)|
```

**`<u>` — 12 штук.** Обёртка вокруг `hh.ru,`. Просто снять теги.

```
Было:  Разместите вакансию на <u>hh.ru,</u> Авито Работа
Стало: Разместите вакансию на hh.ru, Авито Работа
```

**`<mark>` — 2 штуки.** В строке 3, вокруг имени файла. Снять теги и заодно починить опечатку.

```
Было:  Приложение: файл <mark>fnancial</mark> i <mark>_models_10_niches.xlsx</mark>
Стало: Приложение: файл financial_models_10_niches.xlsx
```

### 2.2 Нормализовать пробелы

- 947 строк с хвостовыми пробелами → обрезать
- 1949 пустых строк → схлопнуть тройные и более в двойные
- повторные пробелы внутри строк → схлопнуть в один

### 2.3 Починить точечные дефекты

| Что | Было | Стало |
|---|---|---|
| Пробел перед кодом | `см. разделB0.` | `см. раздел B0.` |
| Шапка таблицы | `Испытательный Типичные Роль Обязательные требования Каналы найма Этапы отбора срок и обучение пр` | удалить строку — ниже идёт нормальная таблица с той же шапкой |
| Имя файла | `fnancial_models_10_niches.xlsx` | `financial_models_10_niches.xlsx` |

### 2.4 Защитить заголовок `9:41 Store`

Строка 4487: `## 9:41 Store, точка на Псковской улице — Санкт-Петербург`

Проблема: парсер нарезки ищет шаблон `^\d+\.` и может принять `9:` за номер раздела. Нужно либо переименовать, либо явно исключить из шаблона нумерации.

Варианты:

- `## «9:41 Store», точка на Псковской улице — Санкт-Петербург`
- `## 9:41 Store — точка на Псковской улице, Санкт-Петербург`

Рекомендую первый: кавычки однозначно снимают двусмысленность.

## 3. Что чиним через LLM

Здесь механика не справится — нужно понимать смысл. Поэтому объём строго ограничен: **11 блоков + 46 строк**. Это мало, проверяемо и не даёт модели разгуляться.

### 3.1 Одиннадцать расплющенных OCR-таблиц

Это следы автоконвертации: таблицу распознали как картинку и выдали одной строкой, где шапка перемешана с данными.

Пример, строка 323:

```
Переменная часть Риск текучки и меры<br>Роль Кол-во График/смены Оклад, ₽ Ключевые KPI<br>(% или KPI) удержания<br>Риск высокий.<br>Выручка и<br>Закрепите<br>Сменный график; Премия за число чеков за<br>расписание заране
```

Видно, что здесь перемешаны: названия колонок (`Роль`, `Кол-во`, `График/смены`, `Оклад, ₽`, `Ключевые KPI`, `Переменная часть (% или KPI)`, `Риск текучки и меры удержания`) и содержимое ячеек (`Риск высокий.`, `Выручка и`, `Закрепите`, `Сменный график;`, `Премия за число чеков за`, `расписание заране`).

**Что делать.** Для каждого из 11 блоков:

1. Вырезать блок в отдельный файл.
2. Отдать LLM с задачей: ��Восстанови таблицу. Вот заголовки колонок: [...]. Вот перемешанные данные: [...]. Верни markdown-таблицу. Не выдумывай данные — если значение не восстанавливается однозначно, поставь `—`.»
3. Проверить результат глазами.
4. Вставить обратно.

**Критично:** в этих таблицах оклады, KPI и риски. Модель не должна ничего досочинять. Промпт обязан запрещать выдумывание, а результат — проходить ручную проверку.

Список строк для ремонта: `323, 332, 1582, 1636, 2123, 2130, 2149, 2164, 2171, 2206, 3609`.

### 3.2 Сорок шесть сдвинутых строк

В двухколоночных таблицах текст из ячейки разъехался по строкам. Примеры:

```
строка 119:  ||В закрытой точке были небольшие средний чек и число покупок. В центре оказалось меньше с
строка 151:  |||Сохранили прежние команду|||
строка 152:  ||После смены владельца|и ассортимент на первые два<br>месяазатем|Кофейня закрылась|При по
строка 178:  ||Кофейню|Доход за месяц составлял от<br>10 000 ₽ до 40 000 ₽ или точка<br>выходила в ноль
строка 183:  |||вырасти на 10–15%, а затем|доступен не каждому|непредвиденные расходы|
строка 184:  |||снизиться|жителю Сибири||
```

Видно три проблемы:

1. **Пустая первая ячейка** — данные уехали вправо.
2. **Склеенные слова** — `месяазатем` вместо `месяца, а затем`.
3. **Разорванные фразы** — `вырасти на 10–15%, а затем` и `снизиться` — это одна мысль, разрезанная на две строки.

**Что делать.** Тот же подход: вырезать таблицу, отдать LLM с задачей «собери строки обратно, склей разорванные фразы, не выдумывай», проверить глазами, вставить.

### 3.3 Остальные 238 строк с пустой первой ячейкой

Из 284 строк с пустой первой ячейкой 46 — явные сдвиги. Остальные 238 могут быть легитимными: например, строка-разделитель внутри таблицы или продолжение предыдущей строки.

**Что делать.** Не чинить вслепую. Сначала вывести их списком с контекстом (±2 строки) и просмотреть. Скорее всего большая часть — нормальные продолжения ячеек с `<br>`, которые после снятия тегов склеятся сами.

## 4. Что НЕ трогаем

Важно зафиксировать, чтобы не навредить.

| Не трогаем | Почему |
|---|---|
| Повторяющиеся заголовки подразделов | Это структура: у каждой ниши свой «Рыночный фон» |
| Дисклеймер про файл финмоделей (10 раз) | Честно повторяется в каждой нише |
| Разные цифры в одноимённых таблицах | У кофейни и пекарни разные финмодели |
| Формулировки кейсов | Это реальные истории, их нельзя «улучшать» |
| Налоговые ставки и суммы штрафов | Любая правка = риск исказить юридически значимые данные |
| Структуру заголовков | На ней держится вся нарезка на чанки |

**Правило:** если правка меняет смысл или цифру — её не делаем. Только ремонт разметки и явных повреждений.

## 5. Нормализация заголовков

Заголовки в документе дрейфуют: один и тот же подраздел назван по-разному в разных нишах.

| Вариант A | Вариант B | Что это |
|---|---|---|
| `Типовые сценарии закрытия в первые 6–12 месяцев` (8×) | `Закрытия в первые 6–12 месяцев работы` (2×) | Один подраздел |
| `Чек-лист сотрудника на смену/день` (8×) | `Чек-лист сотрудника на день` (2×) | Один подраздел |

**Что делать.** Привести к единому виду — взять вариант A как канонический, потому что он встречается чаще.

**Но:** это правка заголовков, а заголовки участвуют в нарезке. Поэтому менять их надо **до** нарезки, а не после. И зафиксировать канонические названия в `taxonomy.json`.

**Важно:** `section_code` (`N.M`) остаётся главным ключом. Текст заголовка — вторичен. Даже если нормализация что-то пропустит, нарезка не сломается.

## 6. Порядок работ

```
Шаг 1. Снять HTML-разметку        → скрипт, безопасно
Шаг 2. Нормализовать пробелы      → скрипт, безопасно
Шаг 3. Починить точечные дефекты  → скрипт + 2 ручные правки
Шаг 4. Нормализовать заголовки    → скрипт + проверка
Шаг 5. Вывести 284 строки с пустой ячейкой → просмотр глазами
Шаг 6. Починить 11 OCR-блоков     → LLM + ручная проверка
Шаг 7. Починить 46 сдвинутых строк → LLM + ручная проверка
Шаг 8. Финальная проверка         → скрипт валидации
```

Шаги 1–4 — механические, делаются одним прогоном. Шаги 5–7 — ручные, требуют внимания.

**Почему такой порядок.** Сначала снимаем разметку, потому что `<br>` мешает увидеть реальные границы ячеек. Потом чиним содержимое — уже по чистому тексту.
